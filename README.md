# Auth System – Full Stack

**Frontend:** HTML, CSS, vanilla JS  **Backend:** Node.js, Express.js, MongoDB (Mongoose)

The browser only shows forms and messages. Everything else – validation, password hashing,
tokens, sessions, lockout, reset links, page access rules – is done on the server.

## Run

Requirements: Node.js 18+ and MongoDB (local or MongoDB Atlas). Deploying? See "Deploy on Render + MongoDB Atlas" below.

    npm install
    npm run setup      # creates .env with a random JWT_SECRET
    npm start          # http://localhost:3000   (npm run dev = auto-restart)

Edit `.env` if your MongoDB is not at `mongodb://127.0.0.1:27017/auth_system` (e.g. Atlas URI).

**Forgot password in development:** if `SMTP_HOST` is empty, the reset link is printed in the
server console. Add SMTP settings to `.env` to send real emails.

## Structure

    server.js            starts DB + server
    app.js               Express app: security headers, page routes, API
    config/              env settings, MongoDB connection
    models/              User, PasswordReset (TTL), RevokedToken (TTL)
    controllers/         register, login, me, logout, forgot, reset
    routes/              /api/auth/*
    middleware/          auth guards, rate limits, JSON-only check, error handler
    utils/               validation, JWT cookie helpers, mailer
    views/               HTML pages (served by server, guarded)
    public/css, js       style.css, app.js (UI only)

## API

| Method | Route | Auth | Purpose |
|---|---|---|---|
| POST | /api/auth/register | – | create account |
| POST | /api/auth/login | – | login by email or username |
| GET  | /api/auth/me | yes | current user |
| POST | /api/auth/logout | yes | revoke token + clear cookie |
| POST | /api/auth/forgot | – | send reset link (same reply for any account) |
| POST | /api/auth/reset | – | set new password with token |

Pages: `/` `/login` `/register` `/forgot` `/reset` `/dashboard`
(`/dashboard` redirects to login without a session; login/register redirect to dashboard if logged in.)

## Security built in

- bcrypt (cost 12) password hashes; dummy compare for unknown users (no timing leak)
- JWT (HS256) in an **HttpOnly, SameSite=Strict** cookie – never readable by JavaScript; 1 hour, or 7 days with "Remember me"
- Logout stores the token id in MongoDB (auto-deleted at expiry), so it can't be reused
- Reset tokens: random 256-bit, only the SHA-256 hash is stored, 15-minute TTL, one-time use;
  resetting the password invalidates all existing sessions
- Account lockout after 5 wrong passwords (default 15 min, configurable) + per-IP rate limiting
- Helmet security headers + CSP, JSON-only POSTs (CSRF defence), body-size limit,
  string-type validation (blocks NoSQL operator injection)

## Deploy on Render + MongoDB Atlas

Frontend and backend are ONE Node service (Express serves the HTML/CSS/JS), so you deploy a single Render Web Service.

**1. MongoDB Atlas**
1. Create a free M0 cluster.
2. *Database Access* -> add a user (simple password: letters + numbers).
3. *Network Access* -> add `0.0.0.0/0` (Render free instances have no fixed IP).
4. *Connect -> Drivers* -> copy the string and put the database name before `?`:
   `mongodb+srv://USER:PASS@cluster0.xxxxx.mongodb.net/auth_system?retryWrites=true&w=majority`

**2. Push the code to GitHub** (`.env` is git-ignored; never commit it).

**3. Render**
- *New -> Blueprint* -> pick the repo (uses `render.yaml`), **or** *New -> Web Service* with:
  Build `npm ci`, Start `npm start`, Health check path `/healthz`.
- Environment variables:

| Key | Value |
|---|---|
| `NODE_ENV` | `production` |
| `MONGODB_URI` | your Atlas string |
| `JWT_SECRET` | auto-generated by the blueprint (or any random 48+ char string) |
| `BREVO_API_KEY`, `MAIL_FROM` | for reset emails (below) |

`PORT`, `TRUST_PROXY` and `APP_URL` are detected automatically on Render. Set `APP_URL` only for a custom domain.

**4. Reset emails on Render**
Render's free plan blocks SMTP ports (25/465/587), so the app sends mail over HTTPS instead. Priority order:
Gmail API -> Brevo API -> SMTP -> (dev only) console.

*Gmail API (sends from your own Gmail, no domain needed):*
1. Google Cloud Console -> create a project -> enable **Gmail API**.
2. *Google Auth Platform* (old name: OAuth consent screen): User type **External**, add your Gmail as test user, add scope `https://www.googleapis.com/auth/gmail.send`, then **Publish app** (set to *In production*). If it stays in *Testing*, the refresh token expires after 7 days.
3. *Clients* -> Create client -> **Web application** -> Authorized redirect URI: `https://developers.google.com/oauthplayground` -> copy Client ID + Client Secret.
4. Open https://developers.google.com/oauthplayground -> gear icon -> tick **Use your own OAuth credentials** -> paste ID/Secret. In Step 1 enter the scope `https://www.googleapis.com/auth/gmail.send` -> Authorize -> sign in (click *Advanced -> Go to app (unsafe)* on the warning) -> Step 2 **Exchange authorization code for tokens** -> copy the **Refresh token**.
5. Set in Render: `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`, `GMAIL_REFRESH_TOKEN`, and `MAIL_FROM="Auth System <your-gmail@gmail.com>"` (must be that same Gmail).

*Brevo API (alternative):* works reliably only with your own verified domain; `BREVO_API_KEY` + `MAIL_FROM`.
In production, reset links are never printed to logs.

**Notes**
- Free Render services sleep after ~15 idle minutes; the first request afterwards can take up to a minute.
- Health check: `GET /healthz` -> `{"status":"ok"}`.
- Cookies are `Secure` in production (Render gives HTTPS), so login works only over `https://`.

## Before going live

Use HTTPS and set `NODE_ENV=production` (enables Secure cookies), set `APP_URL` to your real domain
if you use one, configure an email provider, and use a managed MongoDB (Atlas).
